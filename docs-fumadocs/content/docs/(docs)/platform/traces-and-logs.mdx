# Traces and Logs

EfficientAI **Call Traces** show how your voice agent behaved on each turn: **Listen** (STT), **Think** (LLM), and **Speak** (TTS), plus call-level latency summaries (**p50 / p90 / p95**).

Use traces when you need to answer: *“Was this call slow because of speech recognition, the model, or TTS?”*

Production call ingest (Vapi, Retell, custom webhooks) is documented in [Calls](/docs/advanced/calls/). In the app, **Traces** and **Calls** live under the same **Calls** sidebar entry, on different tabs.

---

## What you get

During a traced call, EfficientAI:

1. Assigns a **Call ID** (six-digit id shown as `#482931` in the UI).
2. Collects pipeline timing from your agent integration.
3. Groups data into **turns**, computes percentiles, and shows a **waterfall** in the trace detail view.

| Concept | Meaning |
| --- | --- |
| **Trace** | One conversation session (one Call ID) |
| **Turn** | One user speak → agent reply cycle |
| **Listen / Think / Speak** | STT, LLM, and TTS timing for that turn |
| **Response p50 / p90 / p95** | How fast replies were across the whole call |

For definitions and examples of percentiles, see [Latency metrics](/docs/monitoring/call-traces/latency-metrics/).

**Sidebar:** **Calls**

| Tab | What it lists |
| --- | --- |
| **Traces** | Pipeline traces from connected voice agents (for example Pipecat) and phone evaluation runs |
| **Calls** | Production webhook calls (Vapi, Retell, custom) |

### Playground and production calls

| Run type | Where to view pipeline timing |
| --- | --- |
| **Agent Playground → Test Agent** | Playground result → **Call details** → **Pipeline** |
| **Agent Playground → Voice AI** (Retell, Vapi, ElevenLabs) | Call recording detail — **provider** timing, not the Traces tab |
| **Deployed Pipecat agent** (WebRTC or phone) | **Calls → Traces** (same workspace as your API key) |
| **Phone simulations / evaluations** | **Calls → Traces** when pipeline tracing is enabled for the run |
| **Production webhook calls** | **Calls → Calls** |

Telephony carriers move audio only; pipeline timing comes from your agent setup and EfficientAI tracing, not from the carrier dashboard.

## Traces vs provider metrics

| Source | EfficientAI pipeline percentiles? |
| --- | --- |
| **Pipeline / OTLP traces** | **Yes** — see [Latency metrics](/docs/monitoring/call-traces/latency-metrics/) |
| **Vapi, Retell, ElevenLabs (provider fields)** | **No** — use the vendor’s definitions |

If the UI shows **Pipeline** or **OTLP**, use our metrics guide. If it shows a provider name, treat values as vendor-reported.

## Connect a Pipecat agent

1. Sign in and select the **workspace** where traces should appear.
2. Create an **API key** under **Settings → API keys** and note the workspace id.
3. Configure your Pipecat project using the setup guide (env vars and SDK hooks).
4. Run a call, then open **Calls → Traces** in that workspace and refresh after hang-up.

## Logs and debugging

EfficientAI is not a full centralized log platform. For debugging, use:

| Surface | What you see |
| --- | --- |
| **Evaluator results** | Run status, scores, transcripts, and artifacts |
| **Call or trace detail** | Turn timing, transcripts, and metadata |
| **Usage** | LLM, STT, and TTS consumption — [Usage](/docs/advanced/usage/) |

Webhook ingest and evaluations on production calls: [Calls](/docs/advanced/calls/).
