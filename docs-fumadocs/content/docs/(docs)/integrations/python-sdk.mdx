# Python SDK

The Python SDK sends traces from your agent to EfficientAI. Each call shows up under **Observability → Calls**.

Start here. Then pick the next page for what you want to do.

## Before you start

1. Open the **workspace** where traces should appear.
2. Go to **Settings → API keys**.
3. Create a key and copy the workspace **ID**.

## Install

```bash
pip install "efficientai-sdk[otel]"
```

You need Python 3.9 or newer. The `otel` extra installs OpenTelemetry so spans can be exported. Until the package is on PyPI, install from the repository:

```bash
pip install "efficientai-sdk[otel] @ git+https://github.com/EfficientAI-tech/efficientAI.git#subdirectory=sdks/python"
```

## Configure

EfficientAI is self-hosted, so point the SDK at your deployment. Set environment variables, or place a `.env` file in the working directory—the client loads it once when you first construct `EfficientAI` or `AsyncEfficientAI`. Existing environment variables are not overridden.

Example `.env` or shell values:

```bash
# Public hostname with TLS
EFFICIENTAI_BASE_URL=https://efficientai.your-company.com

# Private VPC (HTTP only inside the network)
# EFFICIENTAI_BASE_URL=http://efficientai.internal:8000

EFFICIENTAI_API_KEY=...
EFFICIENTAI_WORKSPACE_ID=...
```

`EFFICIENTAI_BASE_URL` defaults to `http://localhost:8000` when you omit it. Match whatever URL agents can reach: **`https://`** when the platform is on the internet or sits behind TLS termination; **`http://`** is normal for self-hosted installs on a private VPC or LAN where TLS ends at a load balancer or is not used at all.

The API key is sent only to that host. Do not pass absolute URLs to another origin, and avoid turning HTTP client libraries (for example `httpx` or `httpcore`) to debug logging in production—that can print request headers.

OTLP span export uses the same scheme as your base URL (`http://…/api/v1/observability/traces` on a private HTTP deployment). The SDK does not require HTTPS for ingest. The only automatic override is when **base URL is `https://`** but the platform handshake returns an **`http://`** OTLP hint—in that case the client keeps HTTPS so the API key is not sent over plain HTTP.

You can also download a filled-in block from your deployment:

```bash
curl -s "$EFFICIENTAI_BASE_URL/api/v1/observability/traces/setup" \
  -H "X-API-Key: $EFFICIENTAI_API_KEY" \
  -H "X-Workspace-Id: $EFFICIENTAI_WORKSPACE_ID" | jq -r .env_block
```

## Check the key

```python
from efficientai_sdk import EfficientAI

EfficientAI().verify()  # True, or raises AuthenticationError
```

## Environment variables

| Variable | Purpose |
|---|---|
| `EFFICIENTAI_BASE_URL` | Reachable base URL (`https://…` or `http://…` on a private network; default `http://localhost:8000`) |
| `EFFICIENTAI_API_KEY` | API key from Settings → API keys |
| `EFFICIENTAI_WORKSPACE_ID` | Workspace that receives the traces |
| `EFFICIENTAI_OTLP_ENDPOINT` | Override the span ingest URL (default `<base URL>/api/v1/observability/traces`) |

## Upgrading from `efficientai.integrations.efficientai_traces`

The old helpers still work. They now live in `efficientai_sdk.tracing`. New code should use `trace.session()`. Unlike the old setup, it keeps concurrent calls in one process apart.
