# Call Traces overview

**Call Traces** show per-turn **Listen → Think → Speak** timing, transcripts, and call-level latency percentiles (p50 / p90 / p95) for voice agents — without running your own observability stack.

Use this section to understand where traces appear in the UI, how metrics are computed, and how to connect a Pipecat bot.

## What Call Traces are

During a voice call, EfficientAI:

1. Assigns a **6-digit Call ID** (`call_short_id`, shown as `#482931` in the UI).
2. Ingests **OpenTelemetry spans** from your Pipecat bot (or in-process from the Test Agent playground).
3. Groups spans into **turn rows**, computes **p50 / p90 / p95**, and shows a **waterfall** in the Calls hub.

:::info What v1 does not include
Dollar cost from OTLP spans (cost comes from provider `call_data`). Enterprise-scale async ingest (planned). Sharding trace rows across data shards.
:::

## UI surfaces

**Route:** **Observability → Calls** (`/observability/calls`)

One list mixes **Pipeline trace** and **Webhook call** rows (see the **Source** column). **Platform** shows transport (for example WebRTC, phone) or provider (Vapi, Retell, Vobiz).

**Phone** pipeline rows (PSTN evaluation) usually show **turn-level response timing** only unless OTLP spans are also ingested. Full waterfall, pipeline stages, and in-drawer transcript come from **WebRTC + OTLP**; use the linked **evaluation result** for recording and dialogue on phone eval runs.

| Where | Detail view | Metrics source |
| --- | --- | --- |
| **Pipeline trace** row | Pipeline trace drawer | EfficientAI p50 / p90 / p95 when spans are ingested |
| **Webhook call** row | Webhook call drawer | Provider `call_data` |
| **Playground → Test Agent** | Result → **Call details** → **Pipeline** | Evaluator + in-process OTLP (not listed in Calls hub) |
| **Playground → Voice AI** | Call recording detail | Provider `call_data` |

**Deep links:**

| Query param | Opens |
| --- | --- |
| `?trace={uuid}` | Pipeline trace drawer |
| `?obs={call_short_id}` | Webhook call drawer |
| `?result={evaluator_result_id}` | Evaluator call drawer |

## Metrics at a glance

| Source | Median / p50 in UI | Computed by EfficientAI? |
| --- | --- | --- |
| **OTLP / Pipecat** | `response_latency_p50_ms` | **Yes** — see [Latency metrics](/docs/monitoring/call-traces/latency-metrics/) |
| **Vapi playground** | `turnLatency`, `*LatencyAverage` | **No** — provider fields |
| **Retell playground** | `latency.*.p50` | **No** — provider histogram |
| **Test Agent** | Pipeline = OTLP; Analysis = evaluator | **Mixed** |

**Rule of thumb:** If the drawer says **Pipeline** or **OTLP**, our percentile math applies. If it shows **Vapi / Retell / provider metrics**, use the vendor's definitions.

## Scaling FAQ (short)

| Question | Short answer |
| --- | --- |
| How many concurrent OTLP calls today? | **10–20** comfortably on sandbox |
| What limits us? | Sync ingest + JSONB span rewrite per batch |
| What unlocks 500+ concurrent? | Async Celery ingest + S3 span blobs (Phase 2) |
| Are traces sharded? | **No** — catalog Postgres only |
| Auto-close idle traces? | **120 seconds** after last span |

Details: [Architecture & scaling](/docs/monitoring/call-traces/architecture/#scaling).

## API prefix

Customer Pipecat bots export spans to:

```
POST {EFFICIENTAI_API_BASE}/api/v1/observability/traces
```

Session lifecycle: `POST /observability/traces/sessions` and `POST /observability/traces/sessions/{call_short_id}/close`.
