## 1. One-sentence summary

EfficientAI shows **one call detail experience** (drawer + waveform + transcript + cost/latency + timeline) for **four different call sources**: playground Voice AI (Vapi/Retell/ElevenLabs/Smallest), webhook observability calls, test-agent evaluator runs, and Pipecat OTLP pipeline traces.

## 2. What the user sees (surfaces)

### 2.1 Playground has two result experiences (do not confuse them)

Agent Playground (`/playground`) has **two tabs** that look similar but use **different data paths**:

| Tab | What user tests | Row click opens | Full-page route | Drawer panel | Metrics |
| --- | --- | --- | --- | --- | --- |
| **Test Agents** | Our Pipecat voice bundle (web eval) | Full page **or** in-tab drawer | `/playground/test-agent-results/:id` | `EvaluatorCallDetailPanel` | Evaluator scores + **Pipeline** tab (OTLP STT/LLM/TTS) |
| **Voice AI Agents** | External provider (Vapi/Retell/ElevenLabs/Smallest) | Drawer only | `/playground/call-recordings/:id` (legacy) | `ProviderCallTracePanel` | Provider `call_data` cost/latency |

`AgentPlayground.tsx` mounts **two** `TraceDetailDrawer` instances — `evaluatorResultId` for Test Agent, `callShortId` for Voice AI. Only one opens at a time.

**Test Agent full page** (`TestAgentResultDetail.tsx`): transcript, metric scores, speaker segments, and a **Call trace** button that opens the same drawer (Pipeline OTLP waterfall).

### 2.2 All surfaces

| Surface | Route / entry | What opens | Primary data |
| --- | --- | --- | --- |
| **Calls** (unified) | `/calls` | `TraceDetailDrawer` | Observability webhook calls + OTLP traces |
| **Call Traces** | `/call-traces` | `TraceDetailDrawer` (`traceId`) | `synthetic_call_traces` (Pipecat OTLP) |
| **Agent Playground → Voice AI** | `/playground` Voice AI tab | `ProviderCallTracePanel` drawer | Playground `call_recordings` (`source=playground`) |
| **Agent Playground → Test Agent** | `/playground` Test Agents tab | Full page + optional drawer | `evaluator_results` + OTLP trace |
| **Evaluator results** | `/evaluators/results/:id` → Call details | Routed drawer (see §5) | Depends on `call_recording_source` |
| **Legacy full page** | `/playground/call-recordings/:id` | Page + optional drawer | Same as playground recording |

All drawers share the same shell: `TraceDetailDrawer` → one of four inner panels.

## 3. End-to-end architecture

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         TraceDetailDrawer (UI shell)                     │
├─────────────────┬─────────────────┬──────────────────┬──────────────────┤
│ ProviderCall    │ Observability   │ EvaluatorCall    │ SyntheticCall    │
│ TracePanel      │ CallDetailPanel │ DetailPanel      │ TracePanel       │
│ (playground)    │ (webhook)       │ (test agent)     │ (OTLP / Pipecat) │
└────────┬────────┴────────┬────────┴────────┬─────────┴────────┬─────────┘
         │                 │                 │                  │
         ▼                 ▼                 ▼                  ▼
  GET /playground/   GET /observability/  GET /evaluator-   GET /observability/
  call-recordings/   calls/{id}           results/{id}      traces/{id}
  {call_short_id}                         + audio S3        + OTLP spans
         │                 │                 │                  │
         ▼                 ▼                 ▼                  ▼
  call_recordings    call_recordings    evaluator_results   synthetic_call_traces
  source=playground  source=webhook     + audio_s3_key      + otel payloads
```

**Key idea:** The same 6-digit `call_short_id` can exist in **different rows** depending on `source`. The UI must route by `call_recording_source` (`playground` vs `webhook`), not by platform name alone.

**Drawer priority inside `TraceDetailDrawer`:** `callShortId` → `observabilityCallShortId` → `evaluatorResultId` → `traceId`.

## 4. Database & sources of truth

### 4.1 `call_recordings` table

| Column | Meaning |
| --- | --- |
| `call_short_id` | 6-digit ID shown in UI (`#482931`) |
| `source` | `playground` or `webhook` |
| `provider_platform` | `vapi`, `retell`, `elevenlabs`, `smallest`, `custom_websocket`, … |
| `provider_call_id` | Provider's call UUID |
| `call_data` | Full provider JSON blob (transcript, costs, latencies, recording URLs) |
| `evaluator_result_id` | Link to evaluation run, if any |

- **Playground API** (`/api/v1/playground/call-recordings/*`) only returns rows where `source = playground`.
- **Observability API** (`/api/v1/observability/calls/*`) only returns rows where `source = webhook`.
- **DELETE** playground recording is scoped to `source=playground` (webhook rows cannot be deleted from playground).

### 4.2 `evaluator_results` table

Stores test-agent and evaluation runs. May include:

- `call_data.call_short_id` — links back to a `call_recordings` row
- `call_recording_source` — **resolved at read time** from linked `call_recordings.source` (API field added Mar 2026)
- `synthetic_call_trace_id` — link to OTLP trace for Pipecat test-agent runs
- `audio_s3_key` — our S3 copy of audio (used when no playground recording)

### 4.3 `synthetic_call_traces` tables

See [OTLP TDD](https://efficientai.atlassian.net/wiki/spaces/ETD/pages/68616193). Stores Pipecat span batches, derived turns, and waterfall metrics.

## 5. Drawer routing (how we pick the right panel)

Frontend helper: `frontend/src/lib/callDetailRouting.ts` → `resolveTraceDrawerTargets()`

| Input | Drawer props | Inner panel | API used |
| --- | --- | --- | --- |
| `call_short_id` + `call_recording_source=playground` + voice AI platform | `callShortId` | `ProviderCallTracePanel` | Playground call-recording APIs |
| `call_short_id` + `call_recording_source=webhook` + voice AI platform | `observabilityCallShortId` | `ObservabilityCallDetailPanel` | Observability call APIs |
| `evaluator_result_id` (default / no voice-AI routing match) | `evaluatorResultId` | `EvaluatorCallDetailPanel` | Evaluator result + S3 audio |
| `trace_id` / OTLP only | `traceId` | `SyntheticCallTracePanel` | Observability traces APIs |

**Voice AI platforms** (routing set): `vapi`, `retell`, `elevenlabs`, `smallest`.

**Bug we fixed (P0):** Evaluator results from observability evaluate used to open the **playground** drawer whenever `provider_platform` was Vapi/Retell — that 404'd because the recording is `source=webhook`. Routing now uses `call_recording_source`.

**Evaluator panel audio rule:** `CallWaveformPlayer` uses playground proxy audio **only** when `call_recording_source === 'playground'`. Otherwise audio comes from evaluator S3 (`GET /evaluator-results/{id}/audio`).

## 6. Playground Voice AI call detail

### 6.1 Load sequence (fast open)

1. User clicks row in Playground → `TraceDetailDrawer` opens.
2. **Prefetch on open:** `prefetchCallRecordingAudio()` + `prefetchCallRecordingQuery()`.
3. **Placeholder** from list cache (`callRecordingQuery.ts`) shows header immediately (platform, ID, timestamps).
4. **Full fetch:** `GET /api/v1/playground/call-recordings/{call_short_id}` returns `call_data` JSON.
5. `refetchOnMount: 'always'` when cached data has no `call_data` (list rows never include full blob).
6. `VoiceAiCallDetailPanel` renders tabs: Transcript, Cost, Latency, Logs (timeline), Analysis.

### 6.2 Cache guard (`hasCallRecordingDetails`)

A cached recording counts as "complete" only when `call_data` is a **non-empty object**. This prevents list-row placeholders (empty `call_data`) from blocking the full fetch for 30 seconds.

**Known gap:** In-progress calls may have token-only `call_data` (non-empty but no transcript). Cache still treats that as complete until stale — see §14.

### 6.3 Post-call enrichment

After a web call ends, `post_call_processing.py` polls the provider (Vapi/Retell API) and merges metrics into `call_data`. User can click **Refresh** → `POST /call-recordings/{id}/refresh`.

Preserved keys during merge: `ui_surface`, `external_usage_recorded`.

## 7. Audio playback & waveform (how it is measured)

### 7.1 Why we proxy audio

Provider recording URLs (Vapi presigned, Retell S3, ElevenLabs authenticated) often **cannot** be played directly in the browser (CORS, auth headers). We proxy through our API:

```
GET /api/v1/playground/call-recordings/{id}/audio?proxy=true&stereo=false
```

Backend streams from provider with `requests.get(..., stream=True)` and returns `StreamingResponse` (chunked).

### 7.2 Stream-first playback (instant start)

`CallWaveformPlayer` sets `<audio src>` to an **authenticated stream URL** immediately (`buildAuthenticatedApiUrl` adds `token` or `api_key` query param — `<audio>` cannot send auth headers).

**In parallel**, it downloads the full file as `ArrayBuffer` only for **waveform peak extraction** (not required to start playback).

### 7.3 Waveform peak extraction

| Step | Module | What it does |
| --- | --- | --- |
| 1 | `waveformPeaksFast.ts` | Parse WAV header, extract min/max peaks per bar **without** `AudioContext` (fast path) |
| 2 | Fallback | `AudioContext.decodeAudioData` for MP3/other formats |
| 3 | Vapi stereo | If stereo URL exists, upgrade to User + Assistant tracks after mono loads |
| 4 | Cache | `waveformAudioCache.ts` — LRU raw buffers (12) + decoded waveform blobs (10) |

### 7.4 Prefetch

- Row hover / drawer open: `prefetchCallRecordingAudio(callShortId, false)` + `prefetchCallRecordingQuery()`
- `warmCallRecordingQueryFromList()` only writes cache when list row already has non-empty `call_data` (rare — list API omits full blob)

### 7.5 Seekable playback (blob upgrade)

After the full audio buffer downloads for waveform peaks, playback **switches from stream URL to blob URL** (`setBlobFromBuffer`) so the playhead can be dragged after the call ends. Scrubbing is disabled until `playbackSeekable` is true.

## 8. Logs / timeline tab (synthetic, not raw provider logs)

The **Logs** tab shows a **reconstructed end-to-end timeline** from `call_data`, not raw provider log files.

Built by `callTimelineUtils.ts`:

### Vapi timeline events

- Call queued → started
- System prompt, user/agent messages (from `artifact.messages`)
- Per-turn pipeline: STT → endpointing → LLM → voice → pipeline complete (from `artifact.performanceMetrics.turnLatencies`)
- Call ended, analysis summary, success evaluation, cost

### Retell timeline events

- Call started, latency overview (E2E/ASR/LLM/TTS p50)
- Transcript turns from `transcript_object`
- Disconnect reason, call summary, cost

**UI:** `CallEventTimeline.tsx` — vertical rows with **Offset | Category | Event**, search + category filter.

**Raw provider logs:** Backend endpoint `GET /call-recordings/{id}/logs` exists (`provider_call_logs.py` — Vapi gzipped JSONL, Retell `public_log_url`) but UI uses synthetic timeline only. External log link shown when `artifact.logUrl` / `public_log_url` is present.

## 9. Cost & latency panels (what is measured, with examples)

`ProviderMetricsPanels.tsx` reads **provider-native** fields. We do **not** recompute p50/p90 for Vapi/Retell in our backend — we display what the provider returned after post-call poll.

### 9.1 Vapi (playground Voice AI)

**Source:** `call_data.artifact.performanceMetrics` after `post_call_processing.py` merges provider API response.

| UI label | JSON field | Meaning |
| --- | --- | --- |
| Transcriber | `turnLatencies[].transcriberLatency` or `transcriberLatencyAverage` | STT time (ms) |
| Endpointing | `endpointingLatency` | Silence detection after user stops speaking |
| LLM | `modelLatency` | Model time to first token / response |
| Voice (TTS) | `voiceLatency` | TTS generation time |
| Turn total | `turnLatency` | Provider-reported full turn time |

**Example** (one turn from Vapi):

```json
{
  "turnNumber": 2,
  "transcriberLatency": 571,
  "endpointingLatency": 304,
  "modelLatency": 359,
  "voiceLatency": 350,
  "turnLatency": 1287
}
```

The **Latency** tab shows per-turn stacked bars plus session averages from `*LatencyAverage` fields.

### 9.2 Retell (playground Voice AI)

**Source:** `call_data.latency` object from Retell API.

| UI label | JSON field | Meaning |
| --- | --- | --- |
| E2E p50 | `latency.e2e.p50` | End-to-end latency median (provider-computed) |
| ASR p50 | `latency.asr.p50` | Speech recognition |
| LLM p50 | `latency.llm.p50` | Language model |
| TTS p50 | `latency.tts.p50` | Text-to-speech |

These are **provider histogram percentiles**, not our `otlp_mapper` formula. We render them in `RetellCallDetails` and the Logs timeline overview.

### 9.3 OTLP / Test Agent Pipeline tab

Uses the same turn rows as Call Traces — see [OTLP TDD §9](https://efficientai.atlassian.net/wiki/spaces/ETD/pages/68616193) for `metrics.ttfb` → ms and p50/p90/p95 math.

| UI location | Metric | Computed by |
| --- | --- | --- |
| Trace header chips | p50 / p90 / p95 | `compute_trace_latency_summary()` |
| Per-turn waterfall | `stt_ttfb_ms`, `llm_ttfb_ms`, `tts_ttfb_ms` | `otlp_mapper.py` per span |
| List column "Median latency" | `response_latency_p50_ms` | Across turns in that call |

### 9.4 Cost panels

| Platform | Total cost field | Breakdown |
| --- | --- | --- |
| Vapi | `cost` or `costBreakdown.total` | `costBreakdown.stt/llm/tts/transport/vapi` |
| Retell | `call_cost.combined_cost` | `call_cost.product_costs[]` |

Charts: `ProviderCostPanel` + `ProviderLatencyPanel` in `ProviderMetricsPanels.tsx`.

**Transcript tab** uses platform-specific detail components: `VapiCallDetails`, `RetellCallDetails`, `ElevenLabsCallDetails`, `SmallestCallDetails`.

## 10. Test Agent (voice bundle) trace

### 10.1 During call (in-process OTLP — no HTTP hop)

`playground_tracing.py` configures Pipecat pipeline tracing for web-eval sessions:

1. `build_pipeline_tracing_kwargs()` stamps spans with `efficientai.call_short_id` via a `CorrelationSpanProcessor`.
2. Spans export through `InternalOtlpSpanExporter` → writes directly into `trace_service` (same turn mapping as customer OTLP ingest).
3. `flush_playground_tracing()` on call end forces span flush.

**Difference from customer Pipecat bots:** Customer bots POST OTLP over HTTP. Playground test agent uses **in-process** export for lower latency and simpler auth.

**Concurrency note:** A singleton exporter is reconfigured per call via `configure(call_short_id=...)`. Safe when one active playground call per worker; risky with parallel calls in one process (see §14).

### 10.2 After call

- Evaluator result created with `synthetic_call_trace_id`
- `EvaluatorCallDetailPanel` tabs: Transcript, Analysis, **Pipeline** (`SyntheticCallTracePanel` embedded)
- OTLP turns mapped to STT/LLM/TTS waterfall (see OTLP TDD)

**Audio:** evaluator S3 recording via `GET /evaluator-results/{id}/audio` (buffer download into `CallWaveformPlayer` — no stream URL yet).

## 11. Observability (webhook) calls

Ingested via telephony webhooks → `call_recordings` with `source=webhook`.

- List/detail: `/api/v1/observability/calls`
- Live transcript: SSE `/calls/{id}/live-events` (Redis pub/sub during active calls)
- Evaluate: creates `evaluator_result` with copied `call_data` + `call_short_id`
- UI: `ObservabilityCallDetailPanel` (provider-specific detail components)

**Gap (P1):** Audio still uses native `<audio src=presigned>` instead of shared `CallWaveformPlayer` proxy.

## 12. Pipecat OTLP traces (Call Traces page)

Route: `/call-traces` (legacy `/test-insights` redirects here).

- List: `TestInsights.tsx` → `GET /observability/traces`
- Detail drawer: `SyntheticCallTracePanel` by `traceId`
- Can also embed by `evaluatorResultId` or `callShortId` (e.g. `CustomWebSocketCallDetails`, evaluator Pipeline tab)

Turn latency is computed server-side in `otlp_mapper.py` from span `metrics.ttfb` (seconds → ms) grouped by `turn.number`.

## 13. Caching & performance notes

| Pattern | File | Purpose |
| --- | --- | --- |
| React Query placeholder | `callRecordingQuery.ts` | Instant drawer header from list cache |
| `hasCallRecordingDetails()` | same | Only treat cache as "complete" when `call_data` is non-empty |
| `refetchOnMount: 'always'` | `ProviderCallTracePanel` | Refetch when placeholder lacks `call_data` |
| Stream URL | `api.ts` `getCallRecordingAudioStreamUrl` | Playback before waveform decode |
| LRU audio cache | `waveformAudioCache.ts` | Avoid re-downloading same recording |
| Evaluator placeholder | `evaluatorResultQuery.ts` | Fast test-agent drawer header |

**Known limitation:** Stream + buffer prefetch can mean **two HTTP downloads** per open (stream for play, buffer for peaks). Future: reuse buffer blob for `<audio>` after decode.

**Known limitation:** Just-created playground calls may have minimal `call_data` (tokens/IDs only). Cache may look "complete" for 30s until post-call poll finishes.
